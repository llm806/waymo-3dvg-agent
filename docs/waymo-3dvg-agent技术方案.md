# Waymo 3DVG Agent 技术方案

核对日期：2026-10-23。操作见 [README](../README.md)，待办见[实施任务清单](实施任务清单.md)。

## 任务与原生身份

输入为完整单帧点云、文本及实际来源相机的一张同帧原图与身份／标定；监督是原生 lidar_box。轨迹用于选帧、备用帧、额度和去重，不是时序训练输入。

框顺序 `[cx, cy, cz, length, width, height, heading_rad]`，长度单位米；帧自车坐标 x 前、y 左、z 上，heading 绕 +z 逆时针。图像左右与自车左右分开定义。TaskProfile 保留 geometry-only 契约，日常主线为 geometry + rgb。

| 原始组件 | 身份与用途 |
| --- | --- |
| lidar_box | C/T/O：片段、帧、原生轨迹；类别、框、点数 |
| projected_lidar_box | C/T/O/V：同 ID 官方图像投影 |
| camera_box、camera_to_lidar_box_association | C/T/V/I：独立 2D 框及有限覆盖关联 |
| camera_image、camera_calibration | 原图 C/T/V、标定 C/V |
| lidar、lidar_camera_projection | C/T/L：五雷达双回波与像素对应 |
| lidar_pose、lidar_calibration、vehicle_pose | TOP 逐点位姿补偿、自车位姿及雷达标定 |
| lidar_camera_synced_box、stats | 同步标签辅助／场景统计 |

原生类别为 0 unknown、1 vehicle、2 pedestrian、3 sign、4 cyclist；车型和颜色是视觉属性，不覆盖真值。官方投影矩形不等于实例掩码或可见性证明，不凭 IoU 猜独立 2D 身份。关联缺失不直接拒绝目标，整车与部件不能混为一个原生单位。

WaymoReader 同时识别 waymo_trainset／waymo_valset 中的 training_／validation_ 前缀，拒绝目录与前缀不符及同一 context 跨官方集合；数据清单另检查组件覆盖。候选冻结 official_split，任务冻结 dataset_split；创建与返工只处理对应集合。官方转换沿用实际来源，日常导出先拒绝混选和类型不符，再核对场景与原始来源，不随机拆分或改写官方划分。

## 标注状态机与自然语言

1. **准备：**按轨迹选代表帧和备用视角，冻结来源；官方 SDK 转换完整五雷达双回波，保留 NLZ、传感器、回波、像素索引及 TOP 逐像素补偿。实际目标框内点须大于零。
2. **观察：**核对来源原图、上下文和裁剪。`recognizable-source-rgb-v2` 接受有依据的 clear／partial；完全隐藏、身份不明或 uncertain 不通过。预算内可换相机，最多尝试 3 帧。
3. **消歧：**保留完整原生／图像库存，分批观察真正相关的竞争对象，每批最多 16。证据足够就停止补看；词表无法表达唯一性时保留失败原因，不声称对象本身不可标注。
4. **写作：**默认模型使用已确认 RGB 属性和可靠几何／图像关系写自然英文；建议 10–25 词，必要事实优先，schema 最多 400 字符。`reference_options` 提供经完整竞争库存验证的备选事实组合，不是固定句式。仅低剩余额度、首轮且简单方案已核验时，可本地生成候选句，仍保留两轮盲核验额度。
5. **核验：**新草稿语言规则、属性一致性、声明线索唯一性，以及两轮新上下文盲解析和工具定位。解析端不接收指定目标，改变词表顺序；不能删除未知竞争者换取唯一性。
6. **结束：**最多两次改写，仍受原额度限制。成功为 calibration_hold；证据不足通常为 needs_evidence。反事实只在支持词汇与额度内诊断，未知不写成通过。

目标原始观察与匿名场景观察分别保存，`resolve_target_observation` 去掉明确冲突，生成和核验共用确认结果。体色与车顶色分开；缺失属性不等于没有特征，gray／silver 不作为可靠互斥颜色。部分可见不能证明隐藏特征不存在。

## 属性、地标与表达

已确认类别／车型／原生部件、颜色、衣着、头盔、牌形及显著特征可与安全自车方位、地标关系和明确相机的图像关系联合消歧。

- 地标须在实际来源相机中可辨认且其描述唯一；保留显著颜色、车型或装备等必要属性。不从其它相机借可见性，不把任意真关系当成唯一定位证明。
- 未来可能有用的地标只用于安排观察，假设性可见性不能成为核验证据。建筑／树木自由地标尚无可靠身份链。
- 属性／自车方位或原生地标关系已可唯一定位时，不把来源相机写成重复可见性短语。仅在保留全部原生／未知／图像竞争者的无视角证明成立时简化新草稿，记录原文并完成双轮核验，不改写历史文本。图像排序／图像地标关系及消歧必需的视角保留。
- 图像关系明确 front view、front-left view 等自然视图名；水平排序与相对地标关系保留分离间隔、未知竞争者及组属性要求。整车轮廓不能指派给单个原生部件。
- 新自然生成排除像素边缘、轮廓最高／最低、中心高度和长度排名等技术消歧；历史谓词仍可读取、复核原证据，不据此改写旧结果或旧门槛。
- 新任务采用 `confirmed-road-scene-v2`：优先细分类别、显著属性、自车方位及可靠地标关系；水平画面排序只在必要时使用并明确相机，新草稿禁用上下排序及画面角落线索。从目标确认观察中按类别选择最多三项显著外观并保留可靠自车纵／横方位；不因排序已唯一而删去这些信息。未知或冲突属性不转成声明，去除其它重复线索仍须完整唯一性证明；新草稿检查与低额度回退共用规则，历史冻结文本和核验规则保持。
- 禁止具体距离、距离区间、最近／最远、对象 ID／坐标暗号及未经确认的运动和意图。

## 执行、性能与恢复

准备阶段换帧与运行阶段换帧共同构成任务身份链：准备日志须绑定输入 packet、冻结候选帧与被拒原帧，运行日志从实际输入帧继续。新运行内保留准备凭据，继承任务转交必要日志；查看、审核索引及导出使用同一校验，缺失或冲突仍拒绝，不改写标注内容或监督。准备完成与凭据一次提交；新运行冻结原任务身份，模型调用前及成功提交前共用 `validate_sample_identity` 校验，并核对任务物体链接。元数据失败保留原因且不计成功，不额外调用模型、读取点云或重新哈希整包；导出仍复核实际资产。

执行器 `adaptive-evidence-harness-v75-native-spatial-planning`。FastAPI 单进程，批次协调器调度独立目标线程；目标／模型默认并发 4／4，均最多 4。有限总预算或仅准备任务串行分配目标；原生证据准备及换帧最多两路，元数据、图像与备选帧缓存按线程隔离。官方转换和场景索引更新共用串行锁与常驻 worker，等待时续期并检查取消，拿锁后重查同帧发布结果；证据索引登记单独串行。自定义准备器仍串行，全部目标线程结束后关闭 worker。

`quality/spatial_relations.py` 按策略隔离旧图像关系与新 `native-3d-spatial-relations-v1`。新关系统一原生 3D 框完整轴向分离及几何保护区；自车坐标 x 向前、y 向左、z 向上，车辆地标前后另用其自身 heading。三维上／下还要求水平投影的保守对齐，不把像素高度或远处对象的高度差当作上下关系。缺失几何／点支持及未关联图像对象保持未知。相机限定仅绑定地标外观来源，不提供空间坐标。新图像目录移除像素关系和排序，写作／核验再次拒绝这些声明；联合规划同时考虑非地标方案，完整唯一证明优先，语义失败后排除本轮失败组合再选方案。双轮盲核验仍保留全部候选及逐轮随机编号，关系表对所有候选对称计算、不读取目标或反馈。

新运行冻结 `compound-claim-entailment-v1`：仅从盲解析自己选中的属性限定排序／属性谓词补齐该轮缺失的属性种类，不从写作声明、期望目标或观察结果补猜；已有属性值、显式冲突及不支持声明原样参与校验。原始模型返回和语义推导收据同时保留，两轮各自归一化后仍执行同样的身份、外观与唯一性检查。文本与声明均重复的已失败草稿不再重复核验，仍计写作调用和草稿次数；修改声明的修复可继续。旧记录沿用冻结规则。

观察计划因颜色／身份复核中断时，`precheck_decision` 在目标仍可辨认、缺少优选方案且至少剩余四次调用时，优先按持久化索引接续原定未执行批次。每批结束重新检查剩余额度，保留写作及两轮盲核验；完成批次不重排，旧失败记录不回写。地标补看规划不再排除仍在目标竞争池中的潜在地标，优先具有已验证原生身份和车辆朝向消歧价值的关系，再按缺失属性数与可见区域规划比较对象；规划假设不写作证据，最终仍要求独立唯一地标及完整竞争池证明。

任务开始时执行器忙则写入 `batch_enqueued` 事件并标记 queued，以事件序号实现持久化 FIFO。单批次占用执行槽，批次内仍并发目标；完成后调度下一项，15 秒恢复循环补调度。重复入队保留位置，取消与开始串行；暂停／停止当前任务或共享故障挂起队列，显式继续才解除。排队时冻结方法、目录和供应商意图，重启后不匹配则暂停，不静默采用新配置。刷新或关闭浏览器只终止页面轮询。

`BoxPointIndex` 为单次帧计算建立三轴坐标排序，使用保守范围缩小待算点集，再以原 `inside_oriented_box` 公式、容差和包含边界判断；不采样、归一化或改变原生框。索引仅在该帧数组保持不变期间使用，不跨帧缓存。用于点对应和转换点数诊断。

`identity-first-on-demand-v1` 仅在目标初检提示单独复核可能形成完整证明、且拆批后仍容纳原完整观察计划时，将匿名目标从首批拆出。调度假设不存为观察或准入证据；实际匿名返回后重新核对身份、属性冲突和完整竞争池，唯一才跳过后续，否则沿原计划补看。拆批选择绑定 packet／来源视角并持久化，换帧清除，未知请求不重放。实际观察绑定相机及上下文／细节／场景输入摘要，普通补看不重复发送已可辨认且输入完全相同的候选；新像素、未知／冲突及专门身份复核仍执行。

写作简报显式区分比较组属性与目标额外属性。新草稿若严格匹配已证明的 leftmost／rightmost 短语，可将额外颜色／形状移至谓语，记录原文和修正文；不修改声明事实、历史标注或核验门槛，修正后仍需外观和两轮盲核验。其它句式继续由模型处理。

`WaymoReader` 每个读者仅保留一帧 camera_image 原始行，五路相机和列筛选复用同次解码；按路径、帧和 size／mtime／ctime 失效，返回副本，不改原图或相机身份。原生 Qwen 客户端按目标线程在批次内复用，结束后关闭；配置仍逐目标核对，自定义工厂保留逐目标生命周期。有限总预算在同一事务查询索引摘要；双轮核验后不再重复保存相同状态。

未观察到的物体提前退出地标描述搜索，仍保留为竞争者。同一 packet／来源视角复用观察调度，换视角或换帧重建；不缓存核验结论。派生图像完整哈希可由最多 4 个线程校验，全部完成且错误传播后才使用。性能工具可按 run_id 定向读取。

SQLite WAL 与事务保留权威快照、事件和额度，调用先预留再发送。`run_summaries` 由触发器在同一事务更新，为调度和界面提供去除大型几何库存的摘要，不替代完整核验／导出快照。方法指纹覆盖 app、转换脚本与锁文件，不包含密钥。

模型代码默认 qwen3.8-flash，本地环境可覆盖。关闭深度思考与 SDK 自动重试；场景观察输出最多 16384 token，其它最多 2048。实际模型、请求、返回、usage、时间与错误持久化，不补造缺失内容。

已明确失败且无部分内容的暂时 HTTP 错误最多 3 次退避，确定未发送的连接失败最多两次重试，无效格式最多两次补正；全部受共享冷却、暂停和原额度限制。读取超时 120 秒，流式总时长检查 300 秒，非精确硬中断。未知远端结果跳过，不重放。

普通样本错误隔离；认证、配置、存储、租约等共享故障可能暂停／阻断。每目标及跨任务轨迹累计默认最多 12 次，任务总额度默认不限。服务每 15 秒检查崩溃遗留 running 批次，旧租约 300 秒，要求代码／目录／供应商一致；主动暂停、停止与待启动不自动开始。

人工继续在原任务核对身份、冻结新的执行修订；已完成结果／方法、任务身份和原目标保留，未完成工作回样本起点，累计调用不重置。底层 `/continue` 仅准备，UI `/control resume` 完成准备与启动。后端源码更新时先返回 `backend_restart_required`，重启由用户操作。换帧及等待准备锁时同步续期目标与批次租约。

## 审核、删除与持久化资产

日常定位确认后可接受／拒绝／废弃，拒绝可带反馈返工；结果绑定文本与场景版本，自动未通过的当前版本经正确定位确认和明确人工审批后可纳入可用集与导出；自动失败记录保留，文本／帧／目标变化使审批失效，身份和资源校验保持。独立盲评使用另一套冻结协议。

删除只处理勾选任务。存续续作在事务内接收必要历史账本与运行引用，保留继承样本、原目标及累计额度；多级／分支按任务去重。最后关联任务删除后回收无引用历史，研究引用及祖先保留。补核验、开发核验后代按引用图处理，独立运行不冒充孤立垃圾。

只阻止所选活动任务删除；无关任务可继续运行，确认令牌不绑定无关进度。活动执行器期间保护共用场景／证据和索引。文件暂存与数据库事务支持回滚及重启恢复。

删除预览／提交通过后台操作和进度轮询执行。`run_cleanup_cache` 按快照更新代次失效，缓存完整快照摘要与引用；终态保存时在数据库写锁外计算，随快照提交。资源摘要按路径及 stat 签名缓存，旧记录首次读取后复用。只读规划和文件暂存完成后才开启短写事务，复核所选记录及新增引用再删除；失效则释放写锁后恢复文件。物理清理也在写事务外，不逐页擦除旧负载或整库压缩。有执行器时不扫描将被整体保留的共享缓存，同时保留冻结方法和共享日志；该保留范围绑定确认，不因另一任务完成而扩大。运行器锁只用于短暂活动检查，日志锁仅保护必要的短文件发布。

清理不能按目录名字或版本年龄判断：真实调用、冻结方法、数据库及被引用的完整场景／证据需保留；依赖环境与前端构建也是运行依赖。源码缓存和无活动使用的测试／临时文件才可直接删除。

删除确认同时绑定候选池选择。含已完成任务默认保留已处理轨迹的排除记录，未完成任务默认重新开放；pending／not-needed 等未处理候选不封禁。`candidate_exclusions` 以 context／原生轨迹和来源为键，不依赖已删任务或外部 ZIP，排队派发前重新查询。已有引用与累计额度保持原约束，公开导出和合并规则不变；历史 `samples.jsonl` 仅用于一次性恢复，可在导入后移除。

## 日常导出契约

Waymo-3DRef 只纳入所选已完成任务中的真实模型最终文本、完整自动核验及未被人工拒绝／废弃的结果；同 context/track 保留最新有效标注。

公开 manifest、样本和 scene JSON 不含 schema_version，不公开质量、方法、任务／运行／证据字段。仅支持现行精简结构，内部场景和研究协议仍独立版本化。

| NPZ 数组 | 类型与维度 |
| --- | --- |
| points | float32，N×6：x/y/z/intensity/elongation/range |
| laser_id、return_id | uint8，N |
| range_image_pixel | int32，N×2 |
| camera_projection | int32，N×6 |
| nlz | int8，N |

完整点云保持五雷达、双回波与原生单位；`objects.json` 为全场景原生框监督。每条输入只用来源相机原图，场景目录保存被引用相机并集。scene_id 是系统稳定哈希，官方身份以 context／帧时间／track_id 为准。

标定保留原生雷达／相机参数、自车位姿和相机时序；引用相机提供 K、畸变和 ego2cam，列向量、OpenCV 相机 x 右/y 下/z 前。考虑帧／图像位姿变化，不声称完全补偿滚动快门。

loader／merge 只依赖 numpy/pillow，不要求读取时重算 SHA-256。按 sample_id 去重、拒绝同轨迹不同版本和资源冲突、合并同场景相机与标定、检查兄弟集合 context 隔离；共享锁下暂存校验再提交，失败回滚。用途名称不改变真实官方 split。

公开契约变更须先获用户明确同意。读取／合并／去重／冲突由既有核心用例验证；未检查实际保留包不得声称已验证其兼容。下游训练适配和 3D／BEV Acc 不在当前范围。

## 独立研究与限制

`/api/research` 提供独立盲评、冻结报告与受控发布，认证包使用独立旧格式和门禁，不能与日常精简 ZIP 混称。详见[科研验收协议](科研验收协议.md)。

当前尚无任意自由地标、时序 grounding、分布式调度或系统级守护。模块仍有 quality／datasets 到 agent 的反向依赖，不是严格单向架构。内部自检、回归和局部性能基准不代替独立盲评及持续运行验收。
