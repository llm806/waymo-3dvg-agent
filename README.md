# Waymo 3DVG Agent

面向 Waymo Perception v2.0.1 的英文目标描述标注工具，日常导出数据集名为 **Waymo-3DRef**。核对日期：2026-10-25。

每条训练输入是完整单帧点云、英文描述、该描述实际来源相机的一张同帧原图及身份／标定；监督为目标原生 7-DOF 框。本项目负责标注、核验、人工审核与导出，不负责训练定位网络。

## 安装与运行

在项目根目录的 Windows PowerShell 执行；主环境使用 Python 3.11、uv 和兼容前端依赖的 Node.js（22.12 或以上）。

```powershell
uv sync --locked
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
```

没有 `.env` 时复制 `.env.example` 并填写密钥；已有配置不要覆盖或公开。

| 配置 | 含义 |
| --- | --- |
| `DASHSCOPE_API_KEY` | 模型服务密钥 |
| `DASHSCOPE_BASE_URL` | 与密钥所属区域、服务和套餐匹配的兼容接口 |
| `DASHSCOPE_MODEL` | 代码默认 `qwen3.8-flash`；实际以进程环境及本地 `.env` 为准 |
| `ANNOTATION_MODEL_CONCURRENCY` | 模型请求并发，默认 4，允许 1–4 |

官方点云转换使用 `preprocessing/` 的独立 Linux／WSL x86_64、Python 3.10 和官方 Waymo SDK 环境，不能用主环境替代。`runtime/waymo-python` 可能是它的解释器，不能按临时目录删除。

**2026-10-26 用户已授权：助手修改代码后如需重启，自动安全暂停、重启服务并恢复原任务，无需用户手动操作或重复确认。** 重启前记录任务／队列及累计进度，等待请求保存和执行器退出；正常关闭本项目服务后后台启动单实例，核对健康状态与加载代码版本，再在原任务继续。用户另行暂停／停止的任务保持原意，历史结果、调用和额度保留，结果未知的请求不重放。下面命令也可供用户手动启动。

```powershell
uv run uvicorn app.main:app
```

使用单个服务进程，打开 <http://127.0.0.1:8000>；API 文档为 <http://127.0.0.1:8000/docs>。后端提供 `frontend/dist`，无需另开前端服务。启动时读取 `.env`，已有进程环境变量优先。后端源码或模型配置变化后需重启；前端变化后重新构建并刷新。

退出前先暂停任务，等待已发送请求保存，再按 Ctrl+C。关闭网页不会停止任务。异常退出遗留的 `running` 批次可在旧租约过期、代码／目录／供应商一致后自动恢复；主动暂停、停止与待启动任务不会自动开始。

## 数据准备

训练文件放在 `waymo_trainset/<component>/training_<component>_<context>.parquet`；验证文件放在 `waymo_valset/<component>/validation_<component>_<context>.parquet`。两套目录各有同名的 13 个组件文件夹，保留官方文件名前缀，不是语义类别。新增数据先核对组件覆盖、官方划分及重名冲突，再执行（同时扫描两套目录）：

```powershell
.venv/Scripts/python.exe -B -m scripts.check_dataset
.venv/Scripts/python.exe -B -m scripts.build_catalog
```

前者更新数据清单，默认不做整批内容哈希；后者生成冻结候选目录，仍保留内部来源指纹。刷新网页读取新目录。候选数量不代表已通过标注，实时状态以接口和运行数据库为准。不必预先转换全部帧。

读取器、候选目录和官方转换器支持 training／validation，保留实际来源 `official_split`。创建任务先选择训练集或验证集，仅使用对应官方数据，不从 training 随机拆分或改标；没有对应候选时不能创建。

## 标注流程与文本质量

当前执行器为 `adaptive-evidence-harness-v96-explicit-region-cards`。

完整场景双轮盲核验使用 `explicit-claims-only-v1`：只检查句中实际声明，外观足以唯一定位时不强求地标；“front view”等只限定来源相机。材质、结构和附件等细节须由完整原图确认，真实关系仍核验三维几何，真实歧义与未知身份仍拒绝。历史记录不改写。

新证据使用 `native-3d-spatial-relations-v1`：**空间关系只由原生三维框、坐标和朝向证明**，图像仅确认可见属性与身份。新标注和返工不使用画面上下／左右、像素排序或二维关系限定的地标；自车坐标系与车辆地标自身朝向明确区分。原生上／下关系要求高度分离及水平位置对齐，不能由透视高低或远处物体的高度差推出。缺少三维身份的图像对象仍是未知竞争者，不能充当地标证明空间关系。属性／自车方位已足够时不强加地标；完整唯一方案优先于仍有歧义的关系方案，核验否定后重新选择方案，不反复套用同一关系。历史记录保持原文及冻结规则。

新运行支持“目标属性＋与一辆符合描述车辆的关系”联合消歧，红车等地标不必单独唯一，但完整句子必须唯一定位目标。写作仅输出句子，程序绑定已选证据，遗漏关系提前拒绝；失败后可本地提出完整候选并保留双轮核验。完整场景核验使用与实际发送图像一致的框坐标和不含目标提示的全场景车辆几何关系图，并附全体候选统一编号图及图块，返回目标—地标组合并核对原生朝向，未知竞争者仍保留。

返工结束却没有生成新草稿时，页面保留旧文本供查看，并允许再次提交反馈；审批与返工权限分开。新提交绑定当前失败轮次和旧文本版本，重复点击不重复分配额度，旧文本不能直接审批或导出。

观察期间的颜色／身份复核结束后，按原批次索引继续预算内未完成的竞争对象观察，再决定补看或换帧。车辆地标仍属于目标竞争者时也可进入补看规划，有可靠朝向关系的地标优先；这些调度调整不放宽最终唯一性检查。

盲解析若已选中“某颜色／车型中的最左”等完整条件，仅漏填重复属性字段，新运行可从该轮独立条件补齐并留痕；显式矛盾、未知竞争者及双轮检查仍保留。失败草稿的原文与声明均重复时提前拒绝，避免重复核验消耗额度；旧运行记录保持原结论。

1. 创建期望 1–2000 条自动通过描述的任务，核对候选池后开始；执行器忙时点击开始即加入持久化队列，按点击顺序自动接续。失败后补选；达到目标、候选耗尽、显式额度不足或用户停止时结束，不保证一定补足。
2. 结合完整点云、原生框、官方投影与原图确认目标身份和实际可见属性。局部遮挡、出画、标志牌背面或缺少独立 2D 关联不直接否决，但不能借用遮挡物属性或猜测不可见部分。
3. 按需要观察竞争对象，搜索能唯一指向目标的属性和关系。未知、零点及未观察对象仍保留；缺失属性不等于不存在。
4. **默认由模型写自然英文。** 已核验的唯一描述方案和地标关系提供事实依据，不强迫固定句式；写作失败或预算不足以再支付写作时，可根据已选证据本地提出候选句，仍须通过外观及两轮核验。
5. 检查语言、外观及唯一性，再以两轮新上下文盲解析和工具定位核验。若符号条件仅因歧义失败，且图文身份／外观已通过、预算足够，可由两轮完整场景盲定位复核原文：包含全部匿名原生与同相机图像候选，逐轮随机编号，不提示目标；两轮都支持原文、无未决竞争者且唯一命中同一原生物体才通过。这是模型参与的自动复核，保留协议和真实调用。准备完成与换帧凭据一次提交；模型调用前及成功保存前核对任务、实际帧和物体身份，使用展示／导出的同一轻量校验，失败不计成功。`calibration_hold` 是内部自动诊断通过，不是独立质量认证。

新准备证据采用 `minimal-sufficient-grounding-v1`：一句真实、有依据的自然英文能够唯一对应原生 3D 目标即可。优先显著属性、具体类型、可靠自车方位或可辨认地标，但不强制属性数量、车型、颜色、自车方向或地标组合。属性本身足够就直接描述；空间关系足够也不必堆叠外观。新流程不使用画面排序作为空间线索。未知或冲突属性不编造；建筑、树木等自由地标尚无可靠身份链。

完整来源图像中已确认的属性足够唯一，且该图像物体与原生 3D 框身份已核验时，直接提供带明确来源视图的属性方案，无需再附加排序或地标。来源图像里的未观察、未知、遮挡和身份未决竞争者仍保留；其他相机的小框不无条件阻塞一个已明确限定来源图像的描述。自车／原生关系使用完整原生候选池，图像关系和属性参照明确来源相机。证据不足才补看、换视角／帧；不编造距离、对象身份、运动或意图。既有完成样本的文本、证据和冻结规则保持原样；新文本仍需真实属性／身份、完整相关竞争池唯一性和双轮核验。

新草稿偏好 `traffic-scene-v1` 并遵守原生三维约束：先搜索物体显著特征／具体类别、自车相对方位和可靠三维地标关系，画面排序及边缘截断不进入新文本的可选线索；证据不足先补看或换视角／帧，不以截断猜测靠近自车。新流程不会因历史边缘或排序方案提前省略预算内的竞争对象观察；仍可定向补看遗漏属性及地标的竞争者，补看规划按不含边缘／排序的竞争池计算，并预留写作与双轮核验。草稿优先保留确认的车型、颜色、行李架／衣着等特征及有用自车方位，不因句子更短就删成泛称，也不强制补写未知属性。

施工路障支持 `construction barricade` 细分类别、已确认的双色条纹及警示灯特征；双色图案不强行归为单一主色。显著特征需进入结构化观察，不能只留在解释中。来源相机匿名观察发现目标检查遗漏属性、且补回这些属性有望形成唯一方案时，在原额度内定向复核；已有竞争对象不重复占用额外地标名额。未知竞争者、原生身份和双轮盲核验仍保留。

夜间可用目标自身已确认点亮的前灯／尾灯，不要求同时识别车色或车型。新证据 `visible-region-v1` 将车身可辨认性与同相机可见灯光检查分开：只有完整原图区域已检查、明确确认没有相应可见灯光且输入凭据一致时，该检查才能排除一个明确相机描述的竞争对象；未检查、噪声／归属不明仍未知，也不能据此声称实体车灯关闭或不存在。最小充分描述优先观察来源相机，完整竞争池仍保留。远处部分遮挡目标可由既有独占点数量、纯度、覆盖率和跨度门槛独立确认 2D／3D 关联，避免同一物体重复竞争；不按颜色或框重叠猜身份。

观察优先覆盖与目标原图范围重叠或同边缘的潜在竞争者，但重叠与边界本身不证明身份。场景关系尚无唯一方案时，补看也包括阻碍显著地标独立辨认的对象，即使它们已被排除为目标候选；仍沿用原补看次数和单批上限，最终地标唯一性与空间关系必须由实际证据通过。

地标也可由“属性＋可靠自车方位／与独立唯一物体的同相机水平关系”共同辨认，保留全部限定语，完整相关竞争池证明唯一后才使用；不循环借目标证明自身。观察先覆盖来源视角的相关对象，缺少唯一方案且只剩四次调用时，优先保留换视角／同轨迹换帧机会，仍受原累计额度限制。

新证据支持按车辆地标自身朝向描述“正前方／正后方”。地标须可辨认、独立唯一且有原生图文身份，使用原生框验证纵向分离、横向对齐及高度；相机限定的地标保留视角。其它红车或缺少 3D 身份的图像对象仍需排除，不能只凭图像印象通过。生成器重复放入谓词列表的外观属性可在保留原声明后整理；未知谓词和改写后未同步的排序条件提前反馈，双轮盲核验保持。返工页面展示具体失败原因、无证据支持的文本片段及未排除候选数量。

默认目标并发 **4**、模型并发 **4**；原生证据准备及换帧最多两路，读取缓存按线程隔离，证据索引登记串行。官方转换仍串行复用 worker，等待时续期并响应暂停；同帧发布后等待者不重复转换。自定义准备器保留串行。任务总调用额度默认不限，每目标及同轨迹跨任务累计默认最多 **12 次**。重试、格式修正、换视角和改写计入额度；最多尝试 3 帧、两次改写。有限总预算任务沿用原额度约束。

部分出画且仍可辨认的目标仍可标注，但新文本用已核验属性和实际场景关系定位；原图边界仅保留为可见性与历史核验证据，未知竞争者不删除。失败目标可经明确授权重新入池，接口 `POST /api/batches/{job_id}/reopen-failed` 支持 `dry_run` 核对及 `additional_calls`（0–12）追加一轮额度。历史调用、费用及失败证据保留，已成功目标和结果未知请求排除；授权只消费一次，暂停继续不重复追加，接口本身不启动任务。

性能优化保留全部核验：证据可能足够时先发目标身份小批次，实际唯一性证明成立才跳过后续竞争对象观察，未知对象仍在竞争池；跳过已明确观察、相机及图像输入完全相同的普通补看，保留不确定性／身份／冲突复核；同帧五路原图一次读取并保留原字节，源文件变化即失效；目标线程在批次内复用模型客户端，结束时关闭。帧内坐标索引加速框内点归属，最终使用原公式；跳过无资格地标的描述搜索；同一来源视角复用观察调度；文件校验采用有界并发。SQLite 摘要表服务调度与状态展示，完整快照仍是核验依据。局部加速不等于整批吞吐已完成实跑验收。

同一批次的不同目标可复用相同帧／相机、供应商／冻结代码、来源组件及完全相同输入上下文的可靠匿名竞争对象观察，内存条数有界，命中仍重验资产。每个新目标自身检查及双轮盲核验保留；冲突／不确定观察不复用，未复用对象重新分组观察。来源调用及依赖保存在快照，删除和中断恢复保留原账本，不重复计费。官方 worker 仍逐帧串行，只对 lidar／lidar_pose／lidar_camera_projection 三个独立文件采用三路读取，不并发改写点云或更改 SDK 公式与合并顺序。

每个观察批次发送前再次检查同行目标刚完成的可靠观察；部分复用只缩小当前批次，完整复用则不发送该请求，批次位置和已预留输入保持，中断后可用持久化证据恢复。图像事实的显式视角／可见性检查同时用于草稿和最终核验；仅在唯一相机已确认、所声明事实为真且准入通过时，为缺少任何图像措辞的新草稿补写该视角，记录提案后仍需外观与双轮盲核验。含模糊图像措辞的草稿交回模型改写，不改旧完成记录。

工作台精简轮询在数据库读取阶段排除不用于展示的观察／工具载荷，仅解析最新准备进度及完整计时间隔。轻量运行投影最多缓存 2048 条，每次核对事务内快照代次；同版本号编辑、删除重建和回滚均失效，完整记录保留。精简 JSON 在同步工作线程中编码；页面隐藏时停止展示轮询，返回时立即刷新，后端任务照常执行。点云视图按实际样本／来源身份复用，进度变化不触发重复绘制，换帧和换物体仍校验。

人工反馈返工会在同等证明等级内优先选择已有证据支持的关系与地标；完整唯一方案仍优先，反馈不代替图像、身份和几何核验。写作仅表达所选证据，新增或反转关系在盲核验前拦截。双轮完整场景核验附原句关系的全来源对象索引，明确主语、地标及参照系，避免把自车后方误读为车辆自身朝向的后方；旧记录及调用不改写。

## 暂停、继续与异常

队列按点击开始的顺序执行，重复点击不重复入队，可取消单个排队任务。当前任务正常完成后自动开始下一项；暂停、停止或共享故障会挂起队列，显式继续后再接续。队列跨服务重启保留；代码／目录／模型变化时暂停对应任务，需显式开始；助手代码修改后的原任务恢复已获授权，其他配置变更不因此自动获准。

点击“继续标注”在**原任务**内恢复，编号、名称、创建时间、原目标和已完成结果保留。未完成工作退回样本起点；代码／目录／模型变化时核对身份并记录新的冻结执行修订，已完成运行保持原方法与文本。累计调用、费用及模型输入输出保留，结果未知的请求跳过且不重放。

后端仍加载旧代码时返回 `backend_restart_required`，由助手按上述授权安全重启并恢复原任务。UI 经 `/control` 的 `resume` 完成准备与启动；底层 `/continue` 仅准备恢复，开始失败可在同一任务重试。

已明确失败且没有部分响应的暂时 HTTP 错误最多追加 3 次退避重试，默认 2／5／15 秒并参考 `Retry-After`；确定未发送的连接失败最多两次重试，无效格式最多两次补正。共享冷却、暂停与额度始终生效。读取超时为 120 秒，流式总时长检查为 300 秒，后者不是独立线程的精确硬中断。

普通样本错误记录后隔离；认证、配置、存储或租约故障可能暂停或阻断。真实模型与网络可靠性、连续数天吞吐仍需实跑验证。

## 人工审核与任务删除

“结果与质量”支持随机抽样、按处理索引选择、隐藏预期目标的定位确认，以及通过／拒绝／废弃。拒绝需填写原因，可在原任务内提交带反馈的 Agent 重试，不创建新任务；反馈原文和旧描述进入模型生成上下文；每次明确返工分配新一轮最多 12 次调用，同一版本的同一次反馈重复提交不重复加额，保留历史调用和费用，新描述仍须通过双轮核验，通过后直接计入原任务的合格数量与导出集合；候选耗尽但未达目标仍可重试，达到目标时须先手动删除一条有效标注，腾出名额后再返工。自动未通过时，先正确确认物体定位，再点击“人工审批通过并纳入可用集”；审批绑定当前文本、来源帧和原生目标，变化即失效，自动失败原因保留，身份与资源核验仍执行。拒绝／废弃的版本排除日常导出。日常即时反馈不计入独立盲评。

任务管理中的删除只处理勾选范围，不连带删除续作。存续任务保留必要样本、历史账本和运行引用；最后一个关联任务删除后清理无引用历史。所选活动任务禁止删除，其他任务不必暂停；无关任务的进度不使删除确认失效。有执行器活动时保留共享场景／证据缓存、索引和日志。核对与删除在后台执行，页面显示当前阶段、记录／目录数量及文件清理进度。引用摘要按快照变化失效，未变化记录复用缓存；历史记录首次建立缓存可能较慢。

扫描、文件暂存、清理和失败恢复均在数据库写事务外进行，提交时只复核变化的引用并更新记录；新出现的关联引用会阻止提交并恢复文件。确认时保留的共享资源不会因其他任务随后完成而扩大清理范围。删除事务失败回滚，中断清理可在服务启动时恢复。已提交但文件仍被占用时可重试清理。

删除确认可选择“将已处理物体重新加入候选池”：含已完成任务时默认不勾选，未完成任务默认勾选。不勾选时仅保留轻量的片段／轨迹排除记录，未处理候选不受影响；勾选仍受其他任务引用及累计额度约束。后续排队任务派发前也会检查排除记录。恢复已删除任务的排除信息只需导出包的 `samples.jsonl`，一次导入后不依赖临时清单；更换片段不会误排除新物体。

临时目录、Python／工具缓存可清理；运行数据库、真实调用、冻结方法、候选排除记录、被任务／审核／导出引用的场景与证据是持久化资产，不能仅因版本较旧而删除。原始数据、`.env`、依赖环境和运行所需前端构建也应保留。

## 导出与合并

日常导出只选择已完成且执行器退出的同一数据集任务。训练／验证混选或导出类型不符时直接提示分开导出，默认文件名跟随任务，场景官方来源仍需一致。仅纳入真实模型生成、自动核验完整通过或当前版本已明确人工审批，且未被拒绝／废弃的样本；人工审批不改写自动失败结论，公开格式保持不变。同 `(context, track_id)` 保留所选范围内最新有效标注；当前不导出一轨迹多帧／多描述并存的训练样本。

公开结构无版本字段，不输出 `quality`、`method_version`、任务／运行／证据来源及失败统计；内部记录与自动核验门槛保留。仅支持现行统一精简结构，不维护旧包兼容层。

```text
manifest.json
samples.jsonl
loader.py
merge.py
scenes/<scene_id>/
  scene.json
  points.npz
  calibration.json
  objects.json
  camera-<id>.jpg
```

样本包含稳定 `sample_id`、文本、官方片段／帧／轨迹、原生类别、7-DOF 目标框和来源相机身份／原图路径。每条只用一张来源原图，同场景保存被引用相机的并集。`objects.json` 为全场景原生框监督，不得泄漏到模型输入。`scene_id` 是系统稳定哈希；官方身份以 context、帧时间和 track_id 为准。

`points.npz` 保持完整单帧五雷达双回波点云；不静默裁剪、采样或归一化。标定保留 K、畸变、ego2cam 及原生位姿／时序，不能宣称补偿全部滚动快门误差。框顺序、单位和数组契约见[技术方案](docs/waymo-3dvg-agent技术方案.md)。

服务器仅需 Python、numpy、pillow，将包内 `merge.py` 与 `loader.py` 放在同一目录：

```bash
python -m pip install numpy pillow
python merge.py --output trainset trainset1.zip trainset2.zip
python merge.py --output valset valset1.zip valset2.zip
python trainset/loader.py --root trainset
```

支持 ZIP、解压目录、通配符和增量追加。同 sample_id 去重，同轨迹不同版本及资源冲突拒绝；合并同场景相机资源和标定，检查兄弟 trainset／valset 的 context 不重叠。共享锁下暂存校验再提交，失败保留原数据。加载不依赖原项目、原始 Parquet 或 Waymo SDK，不要求逐文件重算 SHA-256；loader 是格式参考，不是训练框架适配层。

未经用户明确许可，不改变公开目录、字段、数组类型／维度、坐标、身份、监督、纳入或合并规则。涉及上述实现时须运行既有读取、分包合并、去重与冲突回归；未检查实际保留包不能声称已验证其兼容。

## 检查与代码入口

不启动服务、不调用真实模型的检查：

```powershell
.venv/Scripts/python.exe -B -m pytest tests/test_core.py -q -p no:cacheprovider --basetemp .t-core-check
npm.cmd --prefix frontend run lint
npm.cmd --prefix frontend run build
node --experimental-strip-types --test frontend/tests/core.test.mjs
```

后端维护 10 个核心用例，验证后清理本次测试产物。只读分析指定运行耗时：

```powershell
.venv/Scripts/python.exe -B -m scripts.profile_annotation --run <run_id>
.venv/Scripts/python.exe -B -m scripts.profile_annotation --recent 80
```

诊断提供完整响应／首内容耗时、图像数量、供应商报告的输入缓存命中比例和实测流式输出速率；缺失字段不按零计算，累计工作线程耗时不当批次墙钟吞吐。`--recent` 按运行创建顺序取样，不扫描整批历史，不能与 `--run`／`--job` 混用。服务日志还记录响应头返回前超过一秒的成功 API 读取，不记录查询参数或响应正文；下载流完整时长不在此计时内。
