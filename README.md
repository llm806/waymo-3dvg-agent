# Waymo 3DVG Agent

基于 Waymo Perception v2.0.1 的英文目标描述标注工具，用于构建文本与原生三维目标对应的视觉定位数据集。导出数据集采用 **Waymo-3DRef** 格式。

每条样本包含完整单帧点云、一句英文描述、实际来源相机的同帧原图及标定信息，以同帧原生 7-DOF 框作为监督。项目提供自动标注、核验、人工审核、反馈返工与数据导出功能；模型训练由下游项目完成。

## 主要功能

- **证据驱动标注**：结合原图、点云、原生三维框和身份关联生成自然英文描述。
- **唯一性核验**：检查外观、空间关系及竞争对象，通过两轮独立上下文的盲定位核对目标。
- **人工审核与返工**：支持隐藏目标高亮的定位检查、反馈修改、人工审批和样本废弃。
- **任务管理**：支持有界并发、持久化队列、暂停、继续及异常恢复，并保留调用与审核记录。
- **数据导出与合并**：保留官方训练／验证划分，提供独立的数据加载和分包合并工具。

## 快速开始

以下命令在项目根目录的 Windows PowerShell 中执行。

### 1. 安装依赖并构建前端

```powershell
uv sync --locked
npm.cmd --prefix frontend ci
npm.cmd --prefix frontend run build
```

### 2. 配置模型服务

首次配置时，将 `.env.example` 复制为 `.env`，填写模型服务参数。已有 `.env` 应保留；密钥不应提交到版本库。

| 配置项 | 说明 |
| --- | --- |
| `DASHSCOPE_API_KEY` | 模型服务密钥 |
| `DASHSCOPE_BASE_URL` | 与密钥所属服务、区域和套餐匹配的兼容接口地址 |
| `DASHSCOPE_MODEL` | 模型名称，默认 `qwen3.8-flash` |
| `ANNOTATION_MODEL_CONCURRENCY` | 模型请求并发数，默认 4，取值范围 1–4 |

进程环境变量优先于 `.env`。模型须支持实际接口的图像输入能力；修改模型或后端配置后需要重启服务。

### 3. 启动服务

```powershell
uv run uvicorn app.main:app
```

工作台地址：<http://127.0.0.1:8000>。API 文档：<http://127.0.0.1:8000/docs>。

后端直接提供 `frontend/dist`，无需单独启动前端服务。应用应运行单个后端服务进程；前端源码修改后需重新构建并刷新页面。

## 数据准备

按 Waymo 官方划分存放原始 Parquet 文件：

```text
waymo_trainset/<component>/training_<component>_<context>.parquet
waymo_valset/<component>/validation_<component>_<context>.parquet
```

训练集和验证集各包含同名的 13 个组件目录。保留官方文件名前缀，并检查组件完整性及同名文件冲突。

```powershell
.venv/Scripts/python.exe -B -m scripts.check_dataset
.venv/Scripts/python.exe -B -m scripts.build_catalog
```

上述命令检查两套数据并生成候选目录。原始数据按需转换，无需预先转换全部帧。候选数量与已通过标注的样本数量分别统计，任务进度以工作台为准。

任务冻结对应的 training／validation 来源，返工继承原任务的数据划分，不进行随机拆分或仅修改导出标签。

## 标注与核验

### 使用流程

1. 创建任务，选择训练集或验证集，设置目标数量并核对候选池。
2. 开始标注。执行器忙时，任务进入持久化队列，按开始顺序执行。
3. 系统观察目标及相关竞争对象，搜索有依据的属性与空间线索，生成简洁英文描述。
4. 系统检查文本、外观、原生身份及唯一性，并执行两轮盲定位核验。
5. 在“结果与质量”中检查图像和点云，确认定位或提交反馈返工。
6. 导出已完成任务中的有效样本。

单任务目标数量范围为 1–2000。任务在达到目标、候选耗尽、额度不足或停止操作后结束；候选不足或核验失败可能导致实际数量低于目标。

### 描述质量规则

核心标准是：**一句真实、有依据的自然英文，能够唯一对应场景中的原生三维目标。**

- 优先使用显著外观和明确类别。属性足够时，无需额外添加空间关系；不强制颜色、车型或固定数量的属性。
- 空间关系依据原生三维框、坐标与朝向判断。相机视角用于限定图像来源，不能替代三维方位；车辆地标自身朝向与自车坐标系分别核验。
- 关系应简单、准确且有助于区分目标。明显斜向的自车位置保留完整方位，过远或依据不足的地标不用于新描述。
- 可确认的局部可见区域、标志牌背面及夜间灯光可以提供依据；不可见、未知或有冲突的属性不推断补全。
- 未观察或身份未决的对象仍作为可能的竞争者。缺少属性记录不代表该属性不存在。
- 描述采用自然的指代表达，避免“is the target”等标注术语。反馈提出的属性仍须重新核实，不能直接当作视觉事实。

两轮盲定位使用新的上下文和随机候选编号，不提供预期目标。只有两轮均支持原文、排除未决竞争者并唯一命中同一已核实目标时，自动核验才通过。自动核验属于模型参与的诊断，不等同于独立研究评测；`calibration_hold` 表示内部自动诊断通过。

### 人工审核与返工

人工审核支持定位确认、拒绝、废弃和显式审批。自动未通过的样本可在正确确认物体定位后提交人工审批；审批绑定当前文本、来源帧和原生目标，内容变化后失效。自动失败原因及人工审批来源分别保留，身份与资源完整性检查仍需通过。

反馈返工在原任务中执行。系统区分明确要求、删除要求和建议，并在可核实的证据范围内修改描述。新的描述仍须通过核验；未落实的要求和失败原因会显示在返工进度中。

返工未生成新草稿时，旧文本仅供查看，可再次提交反馈，不能直接审批或导出。任务已达到目标数量时，需先删除一条有效标注腾出名额，才能安排返工。

## 运行控制与调用额度

默认目标并发为 4，模型请求并发为 4，均不超过 4。官方点云转换串行执行；原生证据准备和换帧最多并行两路。

任务总调用额度默认不限；每目标及同轨迹跨任务累计默认最多 12 次。重试、格式补正、换视角和改写均计入额度。明确提交反馈返工时，为该描述版本和反馈分配新一轮最多 12 次调用；重复提交同一轮反馈不重复追加额度。已有有限总预算任务仍受其预算约束。

关闭或刷新网页不会停止后台任务。退出服务前，应暂停任务，等待已发送请求保存和执行器退出，再正常关闭进程。重启后核对服务健康状态与代码版本，通过原任务继续执行。

暂停、停止或共享故障会挂起队列，显式继续后恢复调度。主动暂停、停止及未开始的任务不会因服务启动而自动执行。异常退出遗留的运行任务，在租约及代码、数据目录、供应商一致性检查通过后可恢复。

“继续标注”保留原任务身份、已完成结果及累计调用。代码变化时记录新的执行修订，已完成运行保留原方法与文本。结果未知的请求不会自动重放。后端加载版本与源码不一致时返回 `backend_restart_required`，需先重启；`/control` 的 `resume` 完成恢复与启动，`/continue` 仅准备恢复。

普通样本错误记录后隔离；认证、配置、存储等共享故障可能暂停任务。暂时 HTTP 故障采用有界退避重试，并受暂停控制和调用额度约束。

## 数据导出与合并

导出仅接受已完成且执行器退出的任务。训练集与验证集需分别导出，样本官方来源必须与导出类型一致。

有效样本须通过自动核验或具有当前版本的人工审批，并通过身份及资源检查。拒绝或废弃版本不纳入导出。同一 `(context, track_id)` 保留所选范围内最新有效标注，当前不导出同一轨迹的多帧或多描述版本。

### 导出结构

```text
manifest.json
samples.jsonl
loader.py
merge.py
scenes/<scene_id>/
  scene.json
  points.npz
  calibration.json
  objects.json
  camera-<id>.jpg
```

每条样本使用一张实际来源相机原图；同场景保存被样本引用的相机并集。`points.npz` 保留完整单帧五雷达双回波点云，不裁剪、降采样或归一化。`objects.json` 包含全场景原生框监督，应与训练输入分离。

公开包采用统一精简结构，不包含内部质量状态、执行方法、任务来源或失败统计。目录、字段、数组类型与维度、坐标及框定义详见[技术方案](docs/waymo-3dvg-agent技术方案.md)。

### 加载与合并

将包内 `merge.py` 与 `loader.py` 放在同一目录，安装独立加载所需依赖：

```bash
python -m pip install numpy pillow
python merge.py --output trainset trainset1.zip trainset2.zip
python merge.py --output valset valset1.zip valset2.zip
python trainset/loader.py --root trainset
```

合并支持 ZIP、解压目录、通配符和增量追加。同 `sample_id` 去重，同轨迹版本冲突或资源冲突会明确报错；同场景相机资源及标定按引用合并，并检查训练集与验证集的 context 不重叠。

加载不依赖原项目、原始 Parquet 或 Waymo SDK。`loader.py` 提供数据格式参考，训练框架适配由下游实现。

## 存储与清理

任务删除仅处理选定范围。存续任务引用的样本、调用账本、场景和证据会保留；最后一个关联任务删除后，才清理无引用资源。删除操作支持后台进度与失败恢复。

删除时可选择是否将已处理物体重新加入候选池。重新加入后仍受存续引用及累计调用额度限制，不会重置历史消耗。

原始数据、运行数据库、模型请求与返回、冻结方法、审核记录及被引用的场景和证据属于持久化资产。清理缓存时应保留这些内容，以及 `.env`、依赖环境和运行所需的前端构建。

## 开发与验证

以下检查不调用真实模型：

```powershell
.venv/Scripts/python.exe -B -m pytest tests/test_core.py -q -p no:cacheprovider --basetemp .t-core-check
npm.cmd --prefix frontend run lint
npm.cmd --prefix frontend run build
node --experimental-strip-types --test frontend/tests/core.test.mjs
```

后端维护 10 个核心用例，覆盖定位核验、任务状态、审核、恢复、数据加载、合并及引用保护。测试完成后可清理对应的临时测试目录。

运行耗时分析：

```powershell
.venv/Scripts/python.exe -B -m scripts.profile_annotation --run <run_id>
.venv/Scripts/python.exe -B -m scripts.profile_annotation --recent 80
```

诊断包含响应与首内容耗时、图像数量、供应商报告的输入缓存命中比例及流式输出速率。缺失字段不按零计算，线程累计耗时与任务实际耗时分别统计。
